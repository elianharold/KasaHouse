Decided 2026-09-06 with the user:

- **Database: Neon** (serverless Postgres), provisioned directly at neon.tech (not via Vercel's marketplace). `schema.prisma` uses `url` = pooled string (`DATABASE_URL`) + `directUrl` = direct string (`DIRECT_URL`) for migrations.
- **API host: the user chose Vercel** (2026-09-07, reversing the earlier Railway decision). The API now supports BOTH: `dist/main.js` = long-lived server (Railway/Docker, scaffolding kept: `apps/backend/Dockerfile`, `railway.json`, `render.yaml`, `docker-entrypoint.sh`); `apps/backend/api/index.js` = Vercel serverless handler (boots Nest once per cold start via `src/bootstrap.ts#createApp`, hands requests to the Express instance). `apps/backend/vercel.json`: Root Directory `apps/backend`, `buildCommand` = `vercel-build` script (`prisma generate && nest build` — NO migrate; migrations are run manually with the Neon strings), `outputDirectory: public` (index.html). Function is `api/[...path].js` (catch-all FILENAME, not a rewrite — Vercel "backend framework" projects now rewrite req.url to the destination path, which breaks Nest's `setGlobalPrefix('api/v1')` routing; a catch-all filename keeps the original URL). Vercel auto-selects pnpm 10 (no `packageManager` field).
- **Two big compatibility fixes made 2026-09-07 to enable Vercel:** (1) **downgraded NestJS 12 → 11** everywhere — NestJS 12 + `@nestjs/config@12`/`jwt@12`/`passport@12` are ESM-only (`type: module`), which throws `ERR_REQUIRE_ESM` on Vercel's runtime (worked locally only because Node 24 allows require-of-ESM). v11 line is CommonJS: `@nestjs/common/core/platform-express@11.2.3`, `@nestjs/jwt@11.0.2`, `@nestjs/passport@11.0.5`, `@nestjs/config@4.0.4`, `@nestjs/throttler@6.4.0`, cli/schematics `@11`. (2) **switched Prisma to the `@prisma/adapter-pg` driver adapter** (`pg` + `@prisma/adapter-pg@6.19.3`) — no native query-engine binary to bundle into the Lambda; `PrismaService` constructs `new PrismaClient({ adapter: new PrismaPg({ connectionString, max: 3 }) })` from `DATABASE_URL`. Removed `binaryTargets` from schema. `prisma/seed.ts` also uses the adapter. `prisma migrate` still uses the CLI schema engine (build-time only).
- **Mobile: not server-hosted** — EAS Build → App Store / Play Store.
- **Web (`apps/web`, Next.js 16): Vercel.** Only thing on Vercel. Needs `NEXT_PUBLIC_API_BASE_URL` = Railway API URL + `NEXT_PUBLIC_SITE_URL`. Neon org is Vercel-managed ("WebApps"), DB provisioned via Vercel Storage.
- **Vercel pnpm-12 wrapper bug ("the installed pnpm wrapper is missing"):** caused by `packageManager: pnpm@12.3.4` in root package.json → Vercel's broken pnpm bootstrap. FIX APPLIED 2026-09-07: removed the `packageManager` field entirely (Vercel falls back to its built-in pnpm 9, compatible with lockfile v9); added root `.npmrc` (`node-linker=hoisted`, `dedupe-peer-dependents=false`, `enable-pre-post-scripts=true`) so pnpm 9 and 12 install identically; `apps/web/vercel.json` sets `installCommand: pnpm install --frozen-lockfile --filter @kasahouse/web...` and `buildCommand: pnpm --filter @kasahouse/web build`. **Vercel project Root Directory MUST be set to `apps/web`** or vercel.json isn't read and Next isn't detected.

**Why:** the user asked to reconsider hosting; picking the wrong API host would break Phase 2 chat. **How to apply:** when building Phase 2 chat, assume a persistent Node process (Railway/Render), not serverless. See [[kasahouse-overview]] and [[user-prefers-neon]].
